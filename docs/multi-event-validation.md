# 同場多事件驗證

使用 2015-12-30 湖人對塞爾提克的原始檔 `0021500476.json`，檢查整場 489 個事件。
資料準備方式見 [資料準備](../data/README.md)，來源 SHA-256 與版本見 [Backend 文件](backend-s1.md)。

## 驗證結果

2026-11-14 在 Windows 完成以下檢查。Backend 的轉換政策與 JSON 0.2.0 未變更。

| 結果 | 事件數 | 處理方式 |
| --- | ---: | --- |
| 可轉換 | 482 | 逐筆核對位置、ID、時間與軌跡，共分成 629 個連續片段 |
| 沒有位置資料 | 5 | 明確回報 `Selected event has no moments`，不產生輸出 |
| 相同 timestamp 有不同觀測 | 2 | 明確回報衝突，整個事件停止匯出，不任選其中一筆 |

成功轉換的事件共保留 208,418 筆位置觀測。整場原始事件合計 209,431 筆，兩個被拒絕的
衝突事件合計 1,013 筆；空事件沒有觀測。**事件視窗之間存在重疊，這些數字包含重複時段，
不能視為整場不重複影格數，也不能把 event 當成完整進攻回合。**

驗證內容包括：

- 每個成功事件的所有來源觀測都出現在輸出中，順序與原始索引保持一致。
- 每位球員的 ID、隊伍、位置與名單資料，以及球的位置，均與來源相同。
- 保留 timestamp、game clock、shot clock 與 null；相對時間依實際 timestamp 計算。
- 每個 clip 內時間嚴格遞增；大於 120 ms 的間隙另開片段，每段時間從 0 開始。
- 缺球時輸出 null，缺席球員不補點，重新出現後軌跡另起一段。
- 軌跡索引只涵蓋實際有位置的影格，品質警告連結到正確的來源與輸出影格。
- CLI 對空事件與衝突事件回報失敗，不留下半份匯出目錄。

## 被拒絕的事件

- 空事件：`447`、`517`、`522`、`524`、`544`。
- 衝突事件：`215`、`216`，各有 19 組相鄰觀測使用相同 timestamp 卻有不同內容。
  第一組衝突分別出現在來源 moment 索引 210／211 與 10／11（索引從 0 起算）。
  兩事件涵蓋重疊時段；該組一筆只有球，另一筆有 10 名球員，game clock 也不同，
  因此不能直接拼在一起當成同一個完整影格。

目前保留這兩個事件的原始資料與錯誤紀錄，供人工核對，未修改時間或自動合併觀測。
**測試通過表示程式依政策保留或拒絕資料，並不表示所有事件都能匯出。**

## 如何重跑

先依 README 安裝環境。以下假設原檔放在 `data/raw/`；若原檔在其他位置，請修改
`--input` 與 `SPORTVU_SAMPLE` 的路徑。腳本只適用於這份已核對 hash 的比賽，不會下載資料。

```powershell
.\.venv\Scripts\python.exe scripts/check_sportvu_sample.py `
  --input data/raw/0021500476.json `
  --report outputs/s1-game-validation.json

$env:SPORTVU_SAMPLE = (Resolve-Path data/raw/0021500476.json).Path
.\.venv\Scripts\python.exe -m pytest -q
```

```bash
.venv/bin/python scripts/check_sportvu_sample.py \
  --input data/raw/0021500476.json \
  --report outputs/s1-game-validation.json

SPORTVU_SAMPLE="data/raw/0021500476.json" .venv/bin/python -m pytest -q
```

報告檔已存在時，請另選新名稱；程式不會覆蓋。JSON 報告只存事件編號、計數與錯誤原因，
不存逐影格位置；也不會將 629 個 clip 全部寫入磁碟。腳本逐事件讀取與轉換，不一次載入整場。

重現個別事件匯出時，使用 [Backend 命令](backend-s1.md#匯出)，將 `--event-id` 改為表中的
事件編號，並為 `--output-dir` 選擇新的目錄，例如 `outputs/s1-validation/event-29/`。

本次結果：原有 28 個測試與新增 15 個測試合計 **43 passed**，無 skip；`pip check` 通過。
新案例均使用完整真實事件，未作故障注入。未提供原檔時，資料相關測試會顯示 `skipped`；
明確指定的檔案不存在或 hash 不符時則會失敗。macOS 與其他比賽尚待實測。
