# S1 實作計畫

目標：用原先選定的真實追蹤資料，在 2D 球場上顯示球員位置與軌跡的時間變化，
形成不依賴 S2、S3 或 LLM 的展示。依據 Proposal v6 第 5、6 頁，見
[需求對照](requirements.md)。下列工作尚未開始，驗收門檻為工程建議。

## 工作順序

| 工作包 | 負責 | 具體工作與交付物 | 開始條件／完成條件 |
| --- | --- | --- | --- |
| P0 資料盤點與規格確認 | Backend 主責，兩人確認 | 資料名稱、來源與授權；一個 sample；原始欄位對照；球場與時間定義；示範片段清單；更新 data/README.md | 先取得原先資料集資訊；兩人同意 sample 能支援 S1，資料交換規格可用 |
| P1 讀取與標準化 | Backend | 選定格式的 importer；ID／隊伍對照；時間分段；座標轉換；缺漏與異常報告；小型授權樣本或合成邊界案例的測試 | P0 完成；第一筆、中間與最後一筆可追溯回原始來源，轉換可重現 |
| P2 片段匯出 | Backend，Frontend 協作確認 | manifest、逐影格 JSON、格式驗證、可重現的匯出命令；記錄參數與來源 hash | P1 完成；至少一段真實短片段符合資料交換規格 |
| P3 球場與播放介面 | Frontend | 片段選擇、球場繪圖、球員標籤與顏色、播放／暫停、時間拖曳、軌跡顯示／隱藏與重設；載入／錯誤／缺漏狀態 | P0 規格確認後，可先用標示清楚的示意檔平行開發；完成時須接上 P2 真實輸出 |
| P4 整合與展示驗收 | 兩人 | 準備 outputs/demo；本機啟動步驟；來源與畫面核對；展示紀錄與已知限制 | P2、P3 完成；通過下列驗收，依乾淨 clone 可重建 |

P1／P2 依序完成；P3 在共同格式確認後可與 Backend 平行進行。先打通一段短片段，
再增加片段種類與操作細節。資料品質問題先在 P0／P1 暴露，不靠 Frontend 猜值修補。
實際日期待課程截止日與兩人可投入時間確認後排定。

## P0 必須回答的資料問題

- 來源是逐影格、逐事件還是逐軌跡？檔案包含哪些比賽與可用片段？
- x／y 單位、原點、軸向、場地長寬與全／半場是什麼？是否需要尺度轉換？
- 時間是 timestamp、frame index 或比賽倒數？是否跨節、回合或片段重置？
- 球員與球如何區分？ID 是否穩定？有無隊伍、換人或追蹤中斷資訊？
- 球位置、事件與戰術標籤是否存在？不存在的欄位如何保留未知狀態？
- 授權是否允許組員下載、課堂展示及提交小型測試樣本？

若無法取得原先資料集或必要欄位，不自行改用其他資料集；列出缺少項目，由兩人
決定取得方式或範圍調整。假資料可測介面，不能取代 S1 真實資料交付。

## 前後端第一次交接

1. 共同檢視一個原始 sample，完成欄位、時間與座標對照。
2. 確認 [資料規格](data-contract.md)，先對齊 ID、null、軌跡中斷及檔案路徑。
3. Backend 交付一段真實 JSON、來源／轉換紀錄與品質報告。
4. Frontend 在至少三個時間點核對球員 ID、位置、時間與缺漏行為，記錄發現的差異。
5. 修正資料或繪圖後，共同錄製一次可重現的展示，保存操作步驟與已知限制。

## S1 完成條件

| 編號 | 驗收內容 | 驗證方式 |
| --- | --- | --- |
| A1 | 至少一段來自原先選定資料集的真實片段 | 來源、版本、hash、片段範圍可追溯；不是規格示意 JSON |
| A2 | 時間與座標有明確定義，轉換可重現 | 核對來源及首／中／末樣本，保存轉換參數與適用精度 |
| A3 | 球場、球員位置與身分呈現正確 | 核對長寬比例、原點與軸向；標籤與顏色穩定，未確認資訊顯示未知 |
| A4 | 能呈現時間變化並操作 | 選片段、播放／暫停、拖曳時間、重設；同一 t_ms 顯示相同資料影格 |
| A5 | 能檢視移動軌跡 | 可切換顯示；依實際時間範圍截取，缺漏與中斷不連線；拖曳後不殘留未來軌跡 |
| A6 | 可選資訊與異常不造成假動作或崩潰 | 球位置缺少時隱藏；球員短暫缺席、空片段、檔案錯誤與版本不符有明確狀態 |
| A7 | 環境可重建，S1 可獨立展示 | 依 README 建立環境、取得授權資料、執行匯出與本機展示，不需要 LLM API 或戰術標籤 |
| A8 | 保存展示與限制紀錄 | 記錄片段、操作步驟、資料警告、測試結果與尚未支援的功能 |

首次整合以 Windows 驗收；取得 MacBook 後補做 macOS 環境與瀏覽器驗證，實驗室電腦亦須
重建測試。尚未實測的平台不得標成已通過。若場地規則不明，只能標示已知尺寸與未知部分，
精確球場線條仍待資料盤點確認。

## 測試規劃

| 範圍 | 需要覆蓋的案例 |
| --- | --- |
| 原始讀取 | 合法樣本、缺少必要欄位、錯誤格式；依原格式處理，不先泛化 |
| 時間 | 正常與不等間隔、倒數時間、重置分段、重複或無法解讀的時間 |
| 座標與 ID | 已知座標轉換、軸反向、超界、缺漏、重複 ID、未知隊伍及追蹤 ID |
| 匯出 | JSON 型別、有限數值、版本、manifest／clip 一致性與來源追溯 |
| Frontend | 畫布縮放、時間拖曳、暫停／繼續、片段切換、軌跡重設、缺漏不連線 |
| 整合 | 來源樣本與顯示位置核對；沒有球或 LLM 時仍能完成展示 |

既有 4 個測試只驗證開發環境，不代表已覆蓋以上功能。功能實作時隨工作包加入相應測試。
畫面可人工逐項驗收；如新增前端測試工具，先確認必要性與組員的技術選擇。

## 分支與後續階段

可拆成 `feat/data-import`、`feat/clip-export`、`feat/court-view` 與 `feat/playback-controls`，
每個 PR 附交付物與驗收結果，另一位組員審閱後合併。共同介面更動先更新規格；
資料集、輸出與憑證依既有 .gitignore 保留在各自本機。

S1 驗收後才排入 S2 的距離、移動與關係特徵，再依標籤條件考慮少數戰術辨識。
S3 接續有依據的解釋。影片偵測追蹤、完整自動辨識、EPV、改善建議與互動追問
不納入這次 S1 工作清單。
