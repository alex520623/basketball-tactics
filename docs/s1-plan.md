# S1 實作計畫

S1 的目標是以真實追蹤資料，在 2D 球場顯示球員位置與移動軌跡，並提供時間控制。
範圍依 Proposal v6 第 5、6 頁，見 [需求對照](requirements.md)。

目前已使用 SportVU 比賽 `0021500476`、eventId="2" 完成資料匯出與球場回放。
接下來要由兩人共同核對畫面，並在其他開發電腦重現相同結果。
執行方式見 [S1 Backend](backend-s1.md) 與 [球場回放](local-viewer.md)，
資料使用範圍見 [資料準備](../data/README.md)。

## 工作順序

| 工作包 | 負責 | 交付物 | 目前狀態 |
| --- | --- | --- | --- |
| P0 資料盤點與規格確認 | Backend 主責，兩人確認 | 來源、欄位、時間、座標與使用範圍說明 | 指定單場已盤點；授權與畫面方向待確認 |
| P1 讀取與標準化 | Backend | 串流讀取、ID 對照、時間分段與品質處理 | 指定事件已實作並通過測試 |
| P2 片段匯出 | Backend | JSON 0.2.0、來源 hash 與匯出命令 | 已產生 525 影格的真實片段 |
| P3 球場與播放介面 | Frontend | 球場、位置、軌跡、時間控制與警告檢視 | 已串接真實 JSON；待雙人核對 |
| P4 整合與展示驗收 | 兩人 | 畫面核對紀錄、展示步驟與其他電腦重建結果 | 下一步工作 |

先完成這一段片段的驗收，再增加其他事件或比賽。若資料或畫面有問題，先記錄對應的
球員 ID、時間與來源影格，再判斷應修正資料處理或繪圖。驗收日期由兩人依課程時程安排。

## 資料盤點結果與待確認項目

| 項目 | 已確認 | 待確認 |
| --- | --- | --- |
| 檔案結構 | 單場 JSON 內含事件，各事件含逐筆位置觀測；事件之間可能重疊 | 其他比賽的品質 |
| 座標 | 保留來源 feet；介面用 94×50 ft 參考球場 | 原點與 y 軸對應實際畫面的方向 |
| 時間 | 以來源 timestamp 差播放；跨節、回退或大間隙另分片段 | 與外部影片對齊方式 |
| 身分 | 球員與球以 ID 識別，隊伍取自來源資料 | 其他片段的換人及缺漏情況 |
| 戰術資訊 | 原始檔沒有持球者、攻守角色或戰術標籤 | S2 的標註與判讀方式 |
| 資料使用 | 目前使用指定單場進行開發測試 | 擴大使用、分享與展示的授權 |

詳細欄位見 [SportVU 欄位說明](sportvu-fields.md)。測試缺漏與異常時使用真實片段複本作
故障注入；展示仍使用原始資料轉換的結果。資料不足時，由兩人討論取得方式或調整範圍。

## 接下來的共同驗收

1. 另一位組員依 README 建立環境，準備同一單場資料，執行匯出與回放。
2. 在片段開頭、中間與結尾，比對 JSON 和畫面上的球員 ID、位置與時間。
3. 點選品質警告，核對場外位置；檢查拖曳、倒回與軌跡顯示。
4. 記錄發現的差異，修正後再核對；保存展示操作步驟與已知限制。

## S1 完成條件

| 編號 | 驗收內容 | 驗證方式 |
| --- | --- | --- |
| A1 | 至少一段來自原先選定資料集的真實片段 | 來源、版本、hash、片段範圍可追溯；不是規格示意 JSON |
| A2 | 時間與座標有明確定義，轉換可重現 | 核對來源及首／中／末樣本，保存轉換參數與適用精度 |
| A3 | 球場、球員位置與身分呈現正確 | 核對長寬比例、原點與軸向；標籤與顏色穩定，未確認資訊顯示未知 |
| A4 | 能呈現時間變化並操作 | 選片段、播放／暫停、拖曳時間、重設；同一 t_ms 顯示相同資料影格 |
| A5 | 能檢視移動軌跡 | 可切換顯示；依實際時間範圍截取，缺漏與中斷不連線；拖曳後不殘留未來軌跡 |
| A6 | 可選資訊與異常不造成假動作或崩潰 | 球位置缺少時隱藏；球員短暫缺席、空片段、檔案錯誤與版本不符有明確狀態 |
| A7 | 環境可重建，S1 可獨立展示 | 依 README 建立環境、取得授權資料、執行匯出與本機展示，不需要 LLM API 或戰術標籤 |
| A8 | 保存展示與限制紀錄 | 記錄片段、操作步驟、資料警告、測試結果與尚未支援的功能 |

目前 Windows 已完成初步測試，macOS 與實驗室電腦仍需實際安裝並核對回放。
球場線條使用 NBA 參考幾何；來源座標對應實際畫面的方向仍待確認。

## 測試規劃

| 範圍 | 需要覆蓋的案例 |
| --- | --- |
| 原始讀取 | 合法樣本、缺少必要欄位、錯誤格式；依原格式處理，不先泛化 |
| 時間 | 正常與不等間隔、倒數時間、重置分段、重複或無法解讀的時間 |
| 座標與 ID | 已知座標轉換、軸反向、超界、缺漏、重複 ID、未知隊伍及追蹤 ID |
| 匯出 | JSON 型別、有限數值、版本、manifest／clip 一致性與來源追溯 |
| Frontend | 畫布縮放、時間拖曳、暫停／繼續、片段切換、軌跡重設、缺漏不連線 |
| 整合 | 來源樣本與顯示位置核對；沒有球或 LLM 時仍能完成展示 |

整合版本包含環境 4、Backend 24、回放服務 9、全場驗證 15，共 52 個 Python 案例，
另有 7 個 JS 資料邏輯案例。驗證方式見 [交接指南](handoff.md)。
球場回放已用真實 event 2 進行畫面驗證，詳見 [紀錄](local-viewer.md)。
組員仍須共同核對方向、課堂展示需求與其他電腦的重建結果。

## 分支與後續階段

後續修改從最新 `main` 建立工作分支，例如 `fix/playback-controls` 或 `feat/clip-selection`。
每個 PR 說明變更與驗收結果，由另一位組員審閱後合併。JSON 介面有變動時，同步更新
資料規格與讀取程式；資料集、輸出與憑證由 `.gitignore` 排除。

S1 驗收後才排入 S2 的距離、移動與關係特徵，再依標籤條件考慮少數戰術辨識。
S3 接續有依據的解釋。影片偵測追蹤、完整自動辨識、EPV、改善建議與互動追問
不納入這次 S1 工作清單。
